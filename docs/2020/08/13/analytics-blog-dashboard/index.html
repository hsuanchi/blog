KPI 1. 經營部落格「流量」的北極星指標

*註：北極星指標 (North Star Metric) ，又稱為唯一重要的指標 OMTM ( One metric that matters)

「網站流量」就是由一個又一個的「關鍵字」所組成，如同 Frank 在如何獲得更多的自然搜尋流量？揭曉 SEO 流量組成的黃金公式 – Frank Chiu 文章中提到的黃金公式：

自然搜尋流量的公式 = 「關鍵字 A 搜尋量」 x 「關鍵字 A 點閱率（排名）」+「關鍵字 B 搜尋量」 x 「關鍵字 B 點閱率（排名）」+ 「關鍵字 C 搜尋量」 x 「關鍵字 C 點閱率（排名）」…

所以今天要介紹的第一張圖表就是「搜尋字詞量」：

▍圖表細節

  1. Looker Studio 資料來源：Google Search Console
  2. 圖表：折線 > 組合圖
  3. 維度 X 軸：年月
  4. 指標 Y 軸 (左)：搜尋曝光次數
  5. 指標 Y 軸 (右)：搜尋字詞數量

▍使用說明

將「搜尋字詞量」設定為每月監測 KPI 指標後，會開始留意每篇文章中，使用者可能會搜尋的字詞，並融入文章中。本篇的重點會比較放在儀表板上，所以如何挑選關鍵字就不多琢磨，這邊推薦兩個關鍵字規劃工具，可以參考：

  1. Ubersuggest
  2. Google Ads 關鍵字規劃工具

對照一下 Google Analytics 工作階段 (如下圖)，當 2020/1 月開始監測「搜尋字詞量」後，每個月 Google Search Console 搜尋字詞量約每月一千速度增加，每月的「自然搜尋流量」也有明顯攀升。

KPI 2.「有潛力」的關鍵字排名

在上一個小節提到大量的擴張「搜尋字詞」，擴張總是會有極限的！接下來要介紹的就是如何找出「有潛力」的關鍵字排名圖表：

▍圖表細節

  1. Looker Studio 資料來源：Google Search Console
  2. 圖表：散佈 > 泡泡圖
  3. 維度：搜尋字詞 (Query)
  4. 指標 X 軸：平均排名 (Average Position)
  5. 指標 Y 軸：曝光量 (Impression)
  6. 圖示大小指標：點擊量 (Click)

▍使用說明

如上圖可以看到右上角的機會區，我們鎖定了：

  1. 「搜尋排名」是後段班，代表排名落後的關鍵字
  2. 「曝光量」是前段班，代表有搜尋度的關鍵字
  3. 「圓圈圈」較大，代表這個字詞常被點擊的關鍵字

綜合以上三個維度，形成了右上角的「機會區」，舉個例子像是圖中紅色箭頭標記的關鍵字 「flask session」，目前這個字詞在平均排名 21名，就已經可以有 269 個點擊的成績，如果可以再優化這個關鍵字的排名，會獲得的曝光量和點擊量不容小覷！

相對如果將時間投入在最右下角的區塊 (「搜尋排名」後段班 + 「曝光量」是後段班)，這些先天上就沒有曝光量的字詞，再努力的去優化排名，到前面也不會獲得太多的流量。

接下來挑選到想優化的字詞後，可以透過點擊圓圈圈 (如上圖) 進行篩選。這次點擊的是「flask session」關鍵字詞，下方欄位可以看到和這個字詞有關的頁面是哪些，然後再去優化這些網頁。

至於優化頁面的 SEO 方法，可以參考 2018 年寫的這篇 【數據分析】如何優化Landing Page到達頁? | Max行銷誌，利用簡單的 TF-IDF 去探測排名在第一頁使用的字詞詞頻，來調整自己文章方向和反推 Google 判定的使用者的搜尋意圖。此篇就不多敘述，有興趣可以再去看～

小總結：盡可能提升「有潛力」關鍵字的排名

KPI 3. 優化網頁的載入速度

網頁載入速度對「使用者體驗」和「SEO」的重要性，相信大家都清楚，所以接下來就是要介紹如何監測「網頁的載入速度」的圖表：

▍圖表細節

  1. Looker Studio 資料來源：Google Analytics
  2. 圖表：散佈 > 散佈圖
  3. 維度：網頁標題
  4. 指標 X 軸：平均工作階段
  5. 指標 Y 軸：平均網頁載入時間 (秒)

▍使用說明

如上圖的右上角的「機會區」是每月能帶來高「工作階段」，但「平均網頁載入時間」卻很慢的區塊，像是紅框框內選擇的圓圈，平均載入網頁時間 10 秒，如果能被優化，在 SEO 上會有一定的幫助。

但怎麼去優化常常讓人困擾，以下介紹 4 種 Max 行銷誌 有使用的優化方法，讓大家參考：

優化方法 1. 圖片壓縮

原理：
在不損毀圖片的情況下，進行「圖片壓縮」，來降低網頁存取檔案的大小，是個非常有效的提升網頁載入速度的方法！

WordPress 套件推薦：
老牌套件 Smush – WordPress plugin，僅需點擊 Bulk SMUSH NOW (如下圖)，即可針對圖片進行壓縮優化。如果選擇進階功能，將圖片轉成 Next-Gen (WebP) 的圖片格式並存在 SMUSH 的 CDN 上，需要付費 (6 USD /月) 才能使用。

優化方法 2. Lazy load

原理：
延遲圖片的載入，當使用者滑到圖片時，才會開始載入和顯示圖片，達到節省資源、加速網頁速度的效果。

WordPress 套件推薦：
1. 剛剛推薦的老牌套件 Smush – WordPress plugin 也有提供此功能，使用上也是一鍵啟動就完成了 (如下圖)！

2. 或是使用 Google 出的 WordPress 外掛 Lazy Load 套件：Native Lazyload – WordPress.org

而在 2020/8/11 WordPress 5.5 新版本中，已經開始內建 lazy-loaded images 屬性了！不想使用外掛的朋友們，就快點升級版本吧。News – WordPress 5.5 “Eckstine” – WordPress.org

3. SMUSH 和 Native Lazyload 套件比較：

Google 的 Native Lazyload 套件或 WordPress 5.5 新版本是使用原生的 loading="lazy" 屬性達到 Lazy Load 的效果，可以從 Can I use… 中看到，目前還是有些瀏覽器 (IE、Safari) 是並未直接支援此屬性的，意思是如果使用此原生屬性的寫法，目前在有些瀏覽器上不會實現此功能！

兩個套件的選擇上各有好壞，而我已經使用 SMUSH 來優化壓縮圖片，所以 Lazy Load 就選擇使用 SUMSH 沒有額外再安裝 Native Lazyload 套件。

優化方法 3. Server-Side Cache

原理：
當使用者第一次瀏覽網站的首頁時，Server 將首頁的資訊從資料庫撈出來後，並存在 Server 上的某個地方像是 Redis，當使用者第二次瀏覽首頁時，Server 直接從 Redis 快速的撈出來，不用再回資料庫重新計算，達到減輕資料庫的負載，並且加速網站的載入速度。

WordPress 套件推薦：
推薦和剛剛同一系列的老牌套件：Hummingbird – WordPress.org，使用上也是一鍵啟動，我有開啟的功能是 Page Caching、Browser Caching 和 RSS Caching，提供給大家參考。

優化方法 4. CDN

原理：
簡單來說就是把網站的資料儲存在位於世界各地的資料中心，各個 CDN (Content Delivery Network) 提供者的資料中心都不同，當使用者連接到網站後，會從最接近使用者的資料中心來接收網站內容，以加快網站載入速度。

推薦免費的 CDN 首選當然是：Cloudflare，使用後可以看到不同地區的使用者，會從最近的資料中心接收網站內容 (如下圖)。

KPI 4. 「內部連結」組織架構

為何使用者只瀏覽一頁就跳出了？可能是內容和使用者預期的不同，亦或是沒有把導覽到其他文章的動線指引做好，接下來要介紹的這張圖表，可以快速的篩選出有被優化價值的高跳出率頁面！

▍圖表細節

  1. Looker Studio 資料來源：Google Analytics
  2. 圖表：散佈 > 散佈圖
  3. 維度：網頁標題
  4. 指標 X 軸：工作階段
  5. 指標 Y 軸：跳出率

▍使用說明

如同上圖右上角的「機會區」，我們鎖定了高「工作階段」和高「跳出率」的頁面，代表此區塊的頁面能帶來大量的流量，但使用者卻只瀏覽一頁就跳出了。

而最快和有效的降低「跳出率」方法，常見做法是在內文中增加「內部連結」，像是看完目前這篇文章的朋友，或許會對以下兩篇有興趣：

▍內部連結的重要性

有「目的性」的增加「內部連結」除了可以導引使用者繼續閱讀其他內容外，也可以幫助網路爬蟲根據網頁上的連結來理解你的網站架構，包含總共有多少網頁、哪些網頁是比較重要的頁面，簡單的來說 Google 會透過「內部連結」來分析你的網站。
